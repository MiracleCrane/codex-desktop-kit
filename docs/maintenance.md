# 项目与 Skill 的长期分工

## 唯一维护来源

| 内容 | 唯一负责人 |
| --- | --- |
| 专用代理启动器、最终快捷方式、组合安装与回退 | codex-desktop-kit |
| 模型转发、桥接监督进程、桥接配置事务 | codex-transport-bridge |
| 悬浮球、额度读取、单实例与窗口生命周期 | quota-orb |
| 用户自己的 Agent 偏好和机器路径 | 用户私有上下文及本机配置 |

套件消费组件的 Release ZIP 与 SHA-256。组件仓库拥有自己的源码、测试、安装器和契约；套件不复制或动态修改组件源码。可独立安装不意味着必须使用套件；套件安装也不要求嵌套各组件的快捷方式包装层。

## 改动与发布顺序

1. 在拥有该行为的项目修复，并更新它的测试、文档和版本。
2. 若改变集成接口，先对齐组件契约；保持原入口兼容，或明确新的契约版本。
3. 发布组件固定 tag 和校验资产。
4. 套件更新 `components.json`，验证单装/组合、升级/回退、组件故障和现有配置保留，再发布套件版本。
5. 本机安装由一个操作方负责最终入口与配置；其他会话提供组件版本及证据，避免同时写快捷方式。

组件仓库可以独立发布；套件不会自动追踪多个 main。运行时更新同样核对官方来源、摘要和兼容性后更新 `runtimes.json`，不在用户安装时临时解析 latest。

## 文档与 Agent Skill

README 面向使用者，提供用途、安装、常用操作与限制。docs 保存完整接口、升级、排障和验收；AGENTS.md 约束源码维护边界；SKILL.md 说明 Agent 何时使用项目、先读哪份文档以及操作前提。

个人 Skill 可以保留总排障入口、用户偏好和项目路由，但不再保存第二份程序源码、安装器或通用手册。运行已安装版本时读取匹配版本的文档，开发时读取当前源码；不能让旧程序照着新版命令执行。

机器上的代理端口、安装目录、进程、当前版本与历史验收属于本机记录，每次操作核对实际收据。凭据、账号文件、聊天历史、安装备份、原始日志和 Agent 托管记忆不进入任何公开仓库。
